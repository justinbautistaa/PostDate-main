## MFA setup and recovery

Run `node backend/scripts/setupMfa.js` once to prepare a random `MFA_ENCRYPTION_KEY` in ignored `backend/.env`. The script preserves existing keys and never displays them. Set this same stable secret privately on the host. Do not rotate it casually: existing encrypted authenticator secrets require the original key. Back it up separately with restricted access.

Members enroll under Profile → Settings → Authenticator security. Production staff/admin accounts must enroll during login before they receive a session. They enter the setup key in an authenticator app, confirm the code, and save the eight one-use recovery codes privately. Password recovery does not remove MFA.

## Checks before public launch

Run both complete test suites and the frontend production build. Verify real email delivery, HTTPS cookies, trusted proxy configuration, database authentication/TLS, storage permissions, photo visibility, browser push, off-host backup restoration, and moderation/privacy procedures. A passing local test does not verify any provider account. See GO_LIVE.md and DEPLOYMENT.md.
